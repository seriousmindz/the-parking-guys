Security Policy

The Parking Company Worldwide | Last Updated: October 23, 2025

1. Overview

The Parking Company Worldwide is committed to protecting the security and privacy of our customers, partners, and stakeholders. This security policy outlines our approach to information security and our responsible disclosure program.

2. Security Commitment

We take security seriously and implement industry-standard security measures including:

  • Encryption: All data transmitted between users and our servers is encrypted using TLS 1.3
  • Access Control: Strict authentication and authorization mechanisms
  • Regular Audits: Periodic security assessments and vulnerability scans
  • Data Protection: Secure storage and handling of sensitive information
  • Incident Response: 24/7 monitoring and rapid response procedures
  • Employee Training: Regular security awareness training for all staff

3. Responsible Disclosure Program

We welcome reports from security researchers and the community. If you discover a security vulnerability, please report it responsibly.

How to Report a Vulnerability

What to Include in Your Report

  • Detailed description of the vulnerability
  • Steps to reproduce the issue
  • Potential impact and severity assessment
  • Any proof-of-concept code or screenshots
  • Your contact information for follow-up

Our Commitment to Researchers

  • We will acknowledge receipt of your report within 48 hours
  • We will provide regular updates on our progress
  • We will credit researchers who report valid vulnerabilities (unless anonymity is requested)
  • We will not pursue legal action against researchers who follow responsible disclosure

4. Scope

This security policy applies to:

  • theparkingguys.com
  • parkingcompanyworldwide.com
  • ineedvalet.com
  • ineedvalet.ai
  • All subdomains and related infrastructure

5. Out of Scope

The following are considered out of scope:

  • Social engineering attacks
  • Physical security issues
  • Denial of Service (DoS) attacks
  • Spam or social media issues
  • Issues in third-party services we don't control

6. Security Features Implemented

6.1 HTTP Security Headers

  • X-Content-Type-Options: nosniff - Prevents MIME type sniffing
  • X-Frame-Options: SAMEORIGIN - Prevents clickjacking attacks
  • X-XSS-Protection: 1; mode=block - Enables XSS filtering
  • Referrer-Policy: strict-origin-when-cross-origin - Controls referrer information
  • Permissions-Policy - Restricts browser features

6.2 Content Security Policy (CSP)

We implement a strict Content Security Policy to prevent XSS attacks and unauthorized resource loading:

  • Scripts only from trusted sources
  • Styles only from trusted sources
  • Images from secure HTTPS sources
  • Frames restricted to trusted domains
  • Automatic upgrade of insecure requests

6.3 Data Protection

  • HTTPS Everywhere: All traffic encrypted with TLS 1.3
  • Secure Cookies: HttpOnly and Secure flags enabled
  • Input Validation: All user inputs sanitized and validated
  • Output Encoding: Proper encoding to prevent injection attacks
  • SQL Injection Prevention: Parameterized queries and prepared statements

6.4 Authentication & Authorization

  • Strong password requirements
  • Multi-factor authentication (MFA) available
  • Session management with secure tokens
  • Automatic session timeout
  • Role-based access control (RBAC)

6.5 Infrastructure Security

  • Regular security updates and patches
  • Firewall protection
  • DDoS mitigation
  • Intrusion detection systems (IDS)
  • Regular backups and disaster recovery plans
  • Secure development lifecycle (SDLC)

7. Privacy & Data Handling

We are committed to protecting user privacy:

  • Minimal data collection - only what's necessary
  • Transparent data usage policies
  • Secure data storage with encryption at rest
  • Regular data retention reviews
  • Compliance with GDPR, CCPA, and other regulations
  • User rights to access, modify, and delete data

8. Third-Party Security

We carefully vet all third-party services and ensure they meet our security standards:

  • Regular security assessments of vendors
  • Data processing agreements in place
  • Limited data sharing with third parties
  • Monitoring of third-party security incidents

9. Incident Response

In the event of a security incident:

  • Immediate containment and mitigation
  • Thorough investigation and root cause analysis
  • Notification to affected parties as required by law
  • Implementation of corrective measures
  • Post-incident review and lessons learned

10. Compliance

We maintain compliance with:

  • Payment Card Industry Data Security Standard (PCI DSS)
  • General Data Protection Regulation (GDPR)
  • California Consumer Privacy Act (CCPA)
  • Americans with Disabilities Act (ADA)
  • Industry-specific regulations and standards

11. Security Awareness

We promote security awareness through:

  • Regular employee training programs
  • Security best practices documentation
  • Phishing simulation exercises
  • Security bulletins and updates
